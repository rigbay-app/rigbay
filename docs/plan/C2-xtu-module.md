## Scope (first version)
1. **Probe**: supported only if the Intel XTU service `XTU3SERVICE` exists and the Intel contract DLLs are found in the Intel folder. Clear unsupported reasons (not installed / service stopped / DLLs missing / not an Intel CPU).
2. **Profiles page** (declarative rows): enable row; a "Profiles" group: the profile list built from XTU's `Profiles.xml` plus "Default (BIOS)" plus profiles created in Rigbay (kept in the module settings), the active one marked (same match rule as the old app). Selecting a profile is a hardware change: approval dialog with the PL1/PL2/window values, apply through the proven sequence, read-back shown, revert to the previous profile. Create/edit/delete profile through number rows with the old app's validated ranges. Only the four controls may ever be written: PL2 (id 47), PL1 (id 48), PL2 enable (id 49), time window (id 66); keep the old `Limits` and `Validate` safety boundary. No other XTU control, ever.
3. **Auto-switch** by power source (AC profile / battery profile; power event plus a backup timer; forced re-apply after resume, as in the old app) as settings. Per-profile **hotkeys** through the host hotkey service (refuse XTU's own combos as the old app does). Tray items for the profiles.
4. **Metrics**: the monitor read (`GetValues`, about 1 Hz source) published to the metrics bus: CPU temperature, package power, CPU usage, frequency, PL1/PL2 limits, throttling flags as available; ids `cpu.temp`, `cpu.power`, `cpu.usage`, `cpu.freq` etc. (source `xtu`), with the warm-up skip of the old app. The CSV recorder is NOT part of this task: it will be a separate recorder module that reads the bus. Write the XTU-specific CSV columns and meta of the old recorder into `docs/xtu/RECORDER-NOTES.md` for that future module.
5. **Dashboard summary**: active profile name + CPU temp + package power. **Verbs**: `rigbay xtu status`, `rigbay xtu list`, `rigbay xtu apply <name>` (approval; exit codes as the old app).
6. **Loader**: the host rule for `System.*` assemblies and extra probe paths is task A6 (declared through `probePaths` in `module.json`); use it. Merge branch `feat/loader-rule` (or `main` once it has landed) before you build the real client layer.
7. **Language**: `lang/en.lang`, `lang/vi.lang`, `LangCheck` clean. **Manifest**: id `xtu`, group `power`, honest `requires` (admin, named pipes of XTU3SERVICE, reads `C:\ProgramData\Intel\...\Profiles.xml`, `probePaths` for the Intel folder).
