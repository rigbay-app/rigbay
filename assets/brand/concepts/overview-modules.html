Module marks: two directions as a family

Same grid as Rigbay: 256 canvas, 24 px stroke, pill ends, outer radius 56 / inner 32, one accent per module. Bottom of each direction: the glyph as the icon on a dashboard bay row (24 px) next to the state bar, light and dark.

RECOMMENDED

Direction 1 · Tile

Each module is an occupied bay: a solid accent tile with the glyph knocked out in white. One hue per module, strongest silhouette at 16 px, reads like a Windows 11 app tile.

Direction 2 · Slot

Each module is the empty-bay frame (same radii as the Dock mark) with its glyph lit in the module accent. The frame is neutral ink; only the glyph carries colour, so the rows stay calm.

Risk: The glyph ends up about 35% smaller than in Tile and the frame is the heaviest thing in the icon: at 16 px frame and glyph mush together (see the ×6 pixels), so below 24 px the frame has to be dropped and the glyph used alone.

Recommendation: Direction 1 · Tile. It is the only one that survives 16 px (the brief’s hard test), the glyph is large, and the tile shares the outer radius 56 with the Rigbay Dock mark and the Rigbay app-icon tile, so the family reads at a glance. Slot looks calmer on paper but fails at 16 px, where the frame eats the glyph. The glyphs are shared, so the kit can export a glyph-only quiet form for places where colour must stay free for state. Colours: XTU blue #2F7BFF, PredatorSense magenta #D946B8, Steam access cyan #0A8FB0, template slate #7B8497; each holds at least 3:1 on Mica dark and light. Weakest glyph: Steam access (arc over a post with an arrow can read as ‘redo’); the kit phase should try an alternative. The green bars in the mock-up rows are the state colour, shown only to test the neighbourhood.
