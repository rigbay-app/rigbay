# Integration: what the app needs from the brand kit

For the task that wires the kit into the app (`src/*`, the module folders and `tools/`). This folder was made by the
brand task and **nothing under `src/`, `modules/` or `tools/` was changed by it**. The files here are generated by
`assets/brand/tools/build-integration.mjs` from the masters one level up; do not edit them, change the masters and
rebuild. Guidelines and reasons are in `docs/BRAND.md`.

Status of every item below: **files are built and checked; the app-side code is a proposal and was not compiled or run.**

## 2. Tray icon (it is not rendered with the accent)

| File | Size frames | When |
| --- | --- | --- |
| `Assets/rigbay-tray-light.ico` | 16, 20, 24, 32 | taskbar theme is **light** |
| `Assets/rigbay-tray-dark.ico` | 16, 20, 24, 32 | taskbar theme is **dark** |
| `Assets/rigbay-tray-neutral.ico` | 16, 20, 24, 32 | the theme could not be read |
| `Assets/rigbay-hc-black.ico`, `rigbay-hc-white.ico` | 16 to 256 | high contrast on (black for a light HC theme, white for a dark one) |

Add them next to `rigbay.ico` in `Rigbay.App.csproj`: `<Content Include="Assets\rigbay-tray-*.ico" ... />` and the same
for `rigbay-hc-*.ico` (`CopyToOutputDirectory` and `CopyToPublishDirectory`, like `rigbay.ico`).

Proposal for `TrayHost.Add()` (today it loads `rigbay.ico`): pick the file by the **taskbar** theme, which is
`HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize` value `SystemUsesLightTheme` (0 = dark taskbar;
`AppsUseLightTheme` is the apps theme and is not what the tray sits on). Re-pick on `WM_SETTINGCHANGE` whose `lParam`
string is `ImmersiveColorSet` and call `Native.TrayModify`. `Native.LoadTrayIcon` already loads with
`SM_CXSMICON`, so Windows picks 16, 20, 24 or 32 by DPI from these files (verified at the `LoadImage` level only).

## 3. Title bar mark (follows the Windows accent)

Today `MainWindow.xaml` lines 21 to 25 draw three `Rectangle`s with `RbBrandSlot` and `RbBrandSlotOutline` (defined in
`Styles.xaml`). Replace them by the Dock mark. `xaml/RigbayMark.xaml` holds the path data (a `ResourceDictionary` of
`x:String` keys `RbMarkBay`, `RbMarkBlock`, `RbMarkBaySmall`, `RbMarkBlockSmall`); merge it in `App.xaml` and use:

```xml
<Viewbox Width="20" Height="20" VerticalAlignment="Center">
  <Grid Width="208" Height="208">
    <Path Data="{StaticResource RbMarkBaySmall}"   Fill="{ThemeResource TextFillColorPrimaryBrush}"/>
    <Path Data="{StaticResource RbMarkBlockSmall}" Fill="{ThemeResource AccentFillColorDefaultBrush}"/>
  </Grid>
</Viewbox>
```

- 20 DIP with the small cut (`...Small`); use the full drawing (`RbMarkBay`, `RbMarkBlock`) from 32 DIP up, for example
  on an About page.
- The bay takes the theme's primary text brush and the block the **Windows accent**: that is the whole accent rule.
  High contrast comes for free from `ThemeResource`.
- Proposal: if the accent's hue is within 30° of the state green (154°), red (358°) or amber (37°), draw the block in
  `TextFillColorPrimaryBrush` too (the quiet form), so it can never be read as a state.
- `x:String` as `Path.Data` through `StaticResource` is a common WinUI pattern but **was not compiled here**; if a
  parser complains, inline the string. The `A` commands use `0`/`1` flags as in SVG.
- Fallback if XAML paths are unwelcome: `svg/rigbay-symbol-small.svg` and `svg/rigbay-symbol.svg` with an
  `SvgImageSource` (fixed Bay Violet, no accent binding).

## 4. Module icons on the Dashboard, the Modules page and the navigation pane

Every built-in module gets, **next to its `module.json`** (so they ship in the module's zip):

```
icon.svg            tile, 208 x 208 viewBox            -> Modules page (48 DIP) and Dashboard rows (24 DIP)
icon-glyph.svg      quiet glyph, 176 x 176 viewBox     -> navigation pane (16 DIP), compact lists
icon-16.png icon-24.png icon-32.png icon-48.png icon-64.png icon-128.png     (raster fallbacks; 16 and 24 are small cuts)
icon-unsupported.svg, icon-unsupported-{16,24,32,48}.png                    -> shown when the module's Probe says unsupported
```

Source: `integration/module-icons/<id>/` for `xtu`, `predatorsense`, `steam-access` (copy the folder's files into
`modules/xtu/Rigbay.Module.Xtu/`, `modules/predatorsense/`, and the future Steam access module). The module project
must copy them to the output (`Content Include="icon*.svg;icon*.png" CopyToOutputDirectory="PreserveNewest"`).

Host defaults, embedded in the App (for example `Assets/modules/`): `integration/host-defaults/module-unknown/` (the
neutral tile with a "?", shown when a module has no icon, a bad icon or fails to load) and
`integration/host-defaults/module-template/` (the template's plus tile; also what the `module-template` repo ships).

Which size to load (the smallest PNG that is at least the pixels needed, or the SVG at `DIP × scale`):

| Place | DIP | 100 % | 125 % | 150 % | 200 % | Form |
| --- | --- | --- | --- | --- | --- | --- |
| Navigation pane | 16 | `icon-glyph.svg` or `icon-16.png` | 20 → 24 | 24 | 32 | quiet glyph |
| Dashboard row | 24 | 24 | 30 → 32 | 36 → 48 | 48 | tile |
| Modules page | 48 | 48 | 60 → 64 | 72 → 128 | 96 → 128 | tile |

The `-glyph` PNG sizes also exist in `assets/brand/modules/png/<id>-glyph-<n>.png` if the pane should use rasters.
The Dashboard test (`assets/brand/tests/test-07-dashboard-rows.png`) shows both forms; the recommendation is tiles on
the Dashboard and the Modules page and quiet glyphs in the pane, but it is a one-line switch.

**Unsupported**: show `icon-unsupported.svg` (the same drawing, tile colour replaced by the grey of equal luminance).
For a third-party module that has no such file, draw its `icon.svg` at **45 % opacity**. No grayscale effect (Win2D or
a composition `SaturationEffect`) is needed.

## 5. The module manifest `icon` field: a proposal for Core

Nothing is implemented. This is what Core would need.

```json
{ "id": "xtu", "name": "XTU profiles", "icon": "icon.svg" }
```

| Item | Proposal |
| --- | --- |
| Manifest field | Optional string `icon`: a path **relative to the module folder**, `.svg` or `.png`. Appended to `ModuleManifest` as `string? Icon = null` after `ProbePaths`, so existing code and manifests keep working. |
| Without the field | Core looks for `icon.svg` by convention, then `icon-48.png`; if neither exists the module has no icon and the host shows the "?" tile. |
| Validation (in `ManifestReader`) | No rooted paths, no `..`, the file must resolve inside the module folder and exist; `.svg` ≤ 64 KB, `.png` square ≥ 48 px and ≤ 256 KB. A bad value is a **warning** (`IsError = false`, key `core.manifest.icon-invalid`), never a load failure: the module still loads with the "?" tile. |
| SVG is untrusted input | Reject (warn) a file containing `<script`, `<foreignObject`, `<image`, `<text`, `<style`, or an `href` to anything but `#`. Render only through `SvgImageSource` (no script engine runs). No external fetch. |
| Sidecar files | Same folder and base name: `icon-glyph.svg` (quiet form), `icon-<16\|24\|32\|48\|64\|128>.png` (raster), `icon-unsupported.svg`. All optional. |
| API for the UI | `ModuleEntry` gains `ModuleIcons Icons` with `string? Tile`, `string? Glyph`, `string? Unsupported` and `IReadOnlyDictionary<int, string> Png`, all full paths or null. `PageModel.Icon` (the navigation icon today: a glyph name or a path) falls back to `Icons.Glyph ?? Icons.Tile`. |
| Authors | The rules (grid, one accent colour, tile radius 56 of 208, no third-party logos) are in `docs/BRAND.md` section 10; `module-template` should ship `icon.svg` from `integration/host-defaults/module-template/icon.svg`. |
| Registry | The `registry` repo could list the icon URL for the Modules page catalogue; not needed for installed modules. Out of scope here. |

A test to add with it: a manifest with each bad `icon` value yields one warning and `Icons.Tile == null`.

## 6. Do not

- Do not colour the tray icon with the Windows accent; it is rendered by the shell, not by WinUI.
- Do not put green, red or amber into any icon or tile; state belongs to the state bar.
- Do not use the full drawing below 32 px or the small cut above 48 px.
- Do not rename the files: `rigbay.ico`, `rigbay-tray-light.ico`, `rigbay-tray-dark.ico`, `icon.svg` and friends are the
  names the rest of the kit and the docs refer to.
